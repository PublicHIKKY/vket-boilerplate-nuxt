# /coding - 実装支援コマンド

実装指示を受けて、タスク分解 → レビュー → 実行を行う実装支援コマンドです。

---

## 実行フロー

```
ユーザー: 「○○を実装して」
    ↓
Claude: コードベース調査 → タスク分解 → タスクファイル出力
    ↓
ユーザー: タスクファイルをレビュー・承認
    ↓
Claude: subagentで直列実行
    ↓
完了報告
```

---

## Phase 1: タスク分解

ユーザーの実装指示を受けて、以下を行います：

1. **指示内容の分析**
   - 必要なコードベースの調査（既存実装、関連ファイルの確認）
   - 実装に必要な作業の洗い出し
   - 不明点は調査結果から最適な判断を行う（質疑は行わない）

2. **タスク一覧の作成**
   - 具体的な作業単位に分解
   - 依存関係の整理
   - 該当するスキルがあれば割り当て

3. **タスクファイルの出力**
   - `.claude/tasks/` ディレクトリにMarkdownファイルとして保存
   - ファイル名: `{YYYYMMDD}_{機能名}.md`

### タスクファイル出力先

```
.claude/tasks/{YYYYMMDD}_{機能名}.md
```

### タスクファイルフォーマット

```markdown
# 実装タスク: {機能名}

作成日: {YYYY-MM-DD}
ステータス: 未着手 | 進行中 | 完了

## 依頼内容

> {ユーザーからの依頼プロンプトをそのまま記録}

## 概要

{実装内容の要約}

## 実装方針

{調査結果に基づく判断・方針を明記}

## タスク

- [ ] **1. {作業内容}**
  - Skill: `{スキル名}` または なし
  - 出力: `{ファイルパス}`
  - 依存: なし

- [ ] **2. {作業内容}**
  - Skill: `{スキル名}` または なし
  - 出力: `{ファイルパス}`
  - 依存: 1

## 実行ログ

<!-- 実行時に追記 -->
```

### タスク分解ルール

#### レイヤー構成

このプロジェクトは以下のレイヤー構成に従う。API連携を伴う機能実装では、必要なレイヤーを上から順に検討し、それぞれ独立したタスクとして分解すること。

| 順序 | レイヤー | 検討条件 | 適用Skill |
|------|----------|----------|-----------|
| 1 | Model | 新しいデータ型・Zodスキーマが必要 | `nuxt4-models` |
| 2 | Repository | API通信（外部/内部）が必要 | `repository-creator` |
| 3 | Composable | 状態管理・ビジネスロジックが必要 | `nuxt4-composables` |
| 4 | Component | 再利用可能なUIパーツが必要 | `nuxt4-components` |
| 5 | Page | 画面実装が必要 | `nuxt4-pages` |

**Composable分解時の注意**:
- フォーム入力がある場合: `form/use{機能名}Form.ts` + `use{機能名}.ts` の2タスクに分解
- フォームなしの場合: `use{機能名}.ts` の1タスク

**データバインディングの原則**:
- リアクティブステート（ref, reactive, useState, Composableの戻り値など）はv-modelが有効な場合は**積極的に活用**
- Ht/Ho層では**defineModel**またはinject経由のComposableステートへの直接v-modelを使用し、冗長なProps/Emitsを避ける
- **Composableのprovide**: Pages層以上（Pages、layouts、app.vue、plugins等）でのみ実行可能
- **Composableのinject**: Pages/Ht/Ho層でのみ実行可能（**Hm/Ha層は禁止**）
- API呼び出しはPages層でのみ実行（Ht/Ho/Hm/Haからはemitで委譲）

**inject活用のガイドライン**:
- Pages層でComposableをprovideした場合、Ht/Ho層ではinjectして直接ステートを参照可能
- これによりPages→Ht→Hoのバケツリレー（Props/Emits中継）を削減できる
- Hm/Ha層はinject禁止のため、Ho層からPropsで渡す

#### スキル適用外の処理

上記スキルに該当しない処理（Server API、設定ファイル、ユーティリティ等）は、以下の粒度で個別タスクとして分解する：

- **Server API**: エンドポイント単位（例: `login.post.ts`）
- **設定ファイル**: ファイル単位
- **ユーティリティ**: 機能単位
- **既存ファイルの更新**: 更新内容が明確な単位

#### 分解の原則

1. **1タスク = 1ファイル（または密接に関連する少数ファイル）**
2. **依存関係を明確に**: 下位レイヤーが上位レイヤーに依存
3. **テスト可能な単位**: 各タスク完了時点で動作確認可能であること

### 利用可能なSkills

| Skill | 適用条件 |
|-------|----------|
| `nuxt4-models` | Zodスキーマ・型定義を作成する場合 |
| `repository-creator` | Repository層を実装する場合 |
| `nuxt4-composables` | Composableを実装する場合 |
| `nuxt4-components` | Vueコンポーネントを実装する場合 |
| `nuxt4-pages` | ページを実装する場合 |

---

## Phase 2: レビュー・承認

タスクファイルをユーザーに提示し、承認を得ます。

- **承認**: 「OK」「進めて」等 → Phase 3へ
- **修正依頼**: タスクの追加・削除・変更 → タスクファイルを修正して再提示

---

## Phase 3: タスク実行

承認後、subagentを使って各タスクを直列で実行します。

```
タスク1実行 → 完了 → タスク2実行 → 完了 → ... → 全タスク完了 → 完了報告
```
